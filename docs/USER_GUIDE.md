# PowerTools 使用指南

## 环境要求

- Windows 10/11
- .NET 8 SDK 或 .NET 8 ASP.NET Core Runtime
- 建议使用 Power BI Desktop 保存的 PBIP/PBIR 项目

## 启动

在仓库根目录运行：

```powershell
dotnet run --project .\PowerTools.csproj
```

也可以双击 `start-powertools.cmd`。应用默认打开 `http://localhost:5128`。

## 打开项目

顶部目录框支持以下路径：

- PBIP 项目根目录
- `*.Report` 目录
- `*.SemanticModel` 目录

输入本机目录后点击“打开目录”。解析在本机完成，项目文件不会上传。

## 功能导航

### 模型

- 模型对象：表、字段、层次结构和分区。
- 度量值：查看 DAX、格式字符串、显示文件夹和依赖。
- 计算组：查看优先级、计算项 DAX 和动态格式字符串。
- 模型依赖：查看度量值、字段和计算项的上下游影响。

### 关系与安全

- 关系：检查字段映射、基数、过滤方向和活动状态。
- 安全角色：检查 RLS 表筛选表达式和 OLS 对象权限。

### 书签

- 按 Power BI 保存顺序显示书签组和书签。
- 查看活动页面、应用范围、数据状态、目标视觉对象和筛选器数量。
- 查看每个视觉对象在书签中的显示、隐藏或仅目标状态。
- 如果书签引用的页面已从 PBIR 目录移除，会显示“孤立书签”提示并禁止错误预览。

### 页面布局

- 按 PBIR 中的 X/Y、宽高和 Z 层级还原页面画布。
- 可以显示或隐藏原始隐藏对象。
- 页面存在匹配书签时，可通过“书签”下拉框预览显隐状态。

### 质量检查

“报表质量”首先显示可见数据视觉数量、问题级别、标题与替代文本覆盖率、各层筛选器数量和特殊页面数量。可以按页面、规则类别或关键词缩小问题范围。

点击带有“定位到画布”的问题，会自动切换到对应页面布局并选中视觉对象。页面级问题会切换页面但不会选择某个对象。

当前报表规则覆盖可访问性、布局、结构、导航和筛选器，包括标题、替代文本、Tab 顺序、对象越界、大面积重叠、重复视觉、网格对齐、页面视觉密度、视觉筛选器密度、Tooltip 页面可见性和钻取返回入口。书签明确管理的叠放视觉不会参与重复和重叠判断。

这些结果是静态检查建议，不会改写 PBIR。标题和替代文本的业务质量、特殊交互设计以及刻意叠放仍需报表作者确认。

### 版本比较

输入基线项目和当前项目目录，工具会显示新增、删除和修改对象。可以按变更类型筛选或搜索对象名称。比较只生成内存报告，不会改动项目文件。

### 模型优化

“删除候选”会综合 DAX 依赖、视觉对象字段、关系、层次结构、RLS 和 OLS 生成证据：

- `阻断`：检测到项目内引用，不应删除。
- `项目内候选`：当前 PBIP 项目内未检测到引用，但仍必须人工确认外部报表、Excel/XMLA 客户端、动态字符串、SortByColumn 和源查询。

PowerTools 不会执行删除。建议先在 Git 分支中手动修改 TMDL，再通过版本比较和 Power BI Desktop 验证。

“度量优化”执行静态 DAX 检查，包括变量复用、除法、CALCULATE/FILTER、COUNTROWS、SELECTEDVALUE、嵌套迭代器、重复度量引用、SWITCH 分支和引用规范。静态检查不等同于 Server Timings；对性能规则应在 DAX Studio 或 Performance Analyzer 中验证。

## 常见问题

### 为什么不能直接打开 PBIX？

PBIX/PBIT 是二进制容器。请先在 Power BI Desktop 中另存为 PBIP，再打开生成的项目目录。

### 为什么书签不能在画布中预览？

书签可能来自旧页面，而当前 PBIR 页面目录已经发生变化。此时工具仍展示书签状态用于审计，但不会将其套用到无关页面。

### 工具会修改模型吗？

不会。当前版本只有只读解析和本地可视化能力，不包含保存、删除或覆盖项目文件的操作。
